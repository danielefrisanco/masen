Masen Shipped Phases

A TypeScript library that turns a region and a stylesheet into a standalone SVG map. Deterministic geometry, CSS theming, public-domain data.

Called mapper through Phase 6, then neatline to 0.15.1, and masen from 0.16.0. mapper went because npm had the name. neatline went for a better reason: somebody else's map software already had the word — an Omeka plugin from the Scholars' Lab, fourteen years old, holding neatline.org. Never a registry collision, since it has never been on npm; a collision in the only place that matters for a launch, which is what a person finds when they go looking. masen was picked for having nothing behind it at all. The mp- prefix has survived both renames, because mp is short for map, not for the project.

This page is the record, not the plan. Every phase here shipped, and each keeps its Delivered note — including the ones where the plan turned out to be wrong and measurement said so, which are the entries worth re-reading. The work still open lives in the build plan.

Geometry core

The heart of the library: region in, path strings out. Everything else is presentation on top of this.

  • Region resolvers — named preset, ISO-3166 list, bbox tuple, raw GeoJSON — all normalising to one FeatureCollection
  • Projection registry as a lookup table: mercator, conic-conformal, albers, equal-earth, orthographic
  • Camera via projection.fitExtent() — solves centre, scale and padding in one call
  • Expose map.project() on the result — the single hook the whole annotation layer will hang from
  • Coordinate rounding with geoPath.digits(1); cuts output size well over half
  • Explicit handling for non-contiguous territories, so West Europe does not acquire Guadeloupe
Delivered13 countries, correctly framed. Two things the plan did not predict: masen() had to become async (8 MB of source data cannot ship to every consumer, so geometry loads per region), and five features — Kosovo, Somaliland, N. Cyprus and two disputed areas — carry no id at all, so they take user-assigned codes from the X range rather than a numeric fallback. Those codes are a trap for any region typed by hand. The africa preset carries XS and europe carries XK; a hand-written ISO list will not think to. And leaving Somaliland out of an East Africa map does not leave it blank — it leaves a hole in the Horn, because Somalia's polygon stops at a border the map is not drawing.

Class taxonomy & emitter

The real public API is the DOM shape, not the function signature. Every theme anyone ever writes depends on these names, so they get versioned like an API and changed only on a major.

Theming, palettes & layer control

Mechanically small, because the cascade does the work. No merge logic, no schema, no validation layer.

  • Settle a vocabulary of roughly twelve tokens, named by role — --ink, never --dark-gray
  • Theme resolution: bundled preset name, path to a .css file, or a plain token object
  • Split palette from theme. A theme carries structure — line weights, type, dash patterns, density. A palette carries only colour. Both target users want the same thing: keep the style, change the colours. Because tokens are named by role, a palette is a set of token values, so theme: "minimal", palette: "dusk" is two stylesheets in cascade order and needs no new machinery
  • A layers option that fills slots, never removes them. Turning borders off must empty .mp-borders, not delete it — the stack is the frozen contract, and a document whose shape depends on its options is not one a theme can be written against. The payoff is file size, not appearance: hiding a layer is one CSS rule, but not emitting its path data is real bytes at 50m detail
  • Overrides land as a later declaration on the root element; nothing else to implement
  • Every preset styles .is-highlighted from --accent, so brand colour is one override
  • Reserve --anno, --anno-ink, --neighbour and --furniture-ink in the vocabulary; leave them unused
  • An inlineStyles pass that flattens computed values onto presentation attributes for design tools — and for the renderers that let a presentation attribute beat a stylesheet, which Phase 2 found the hard way
  • Scope every rule to a class derived from the stylesheet itself. A <style> block inside inline SVG applies to the whole HTML page, so two differently themed maps on one page would otherwise overwrite each other. Hashing the resolved CSS keeps the scope deterministic: same theme, same class, byte-identical output
  • A gallery of committed snapshot SVGs, not one. Phase 2 shipped a black map that every string assertion passed — the snapshots have to be worth opening, and they have to cover themes, palettes, projections and canvas shapes. Since extended with a contact sheet — npm run gallery — because forty-two files in a directory is not something anyone opens either. All of them inline on one page, at a size where a flat choropleth is obvious at a glance, and with what each map demonstrates read back off the markup rather than off the test that wrote it, so the page cannot claim a feature a file does not contain
DeliverableTwo themes and two palettes applied end to end, a gallery of renders to look at, and the same map exported for Figma.

Data pipeline

  • Ingest a second dataset — Natural Earth populated places. world-atlas has country polygons and nothing else, so .mp-place, .mp-label and their data-pop / data-rank attributes have no source until this lands. Phase 6 cannot start without it

Presets & fill modes

Design work, not engineering work, and the longest phase for that reason. This is what people will choose the library for — and the thing that separates it from a mapshaper one-liner. If this phase gets cut for time, you have built a worse mapshaper.

The phase opened by finding that the last one had shipped blind. The flattening pass matched class selectors only, so every rule keyed on a data attribute was dropped on the way out — which meant 0.7's choropleth exported as a single flat colour and rivers exported with no stroke at all. Both were correct in a browser, so the gallery looked right to anything that reads <style> and wrong to everything else. Political fill, keyed on data-fill, would have landed in the same hole an hour later.

paper was dropped and atlas kept in its place. atlas was built in Phase 3 and was never in this plan; it fills the printed-map slot paper was drawn for, and shipping both would have put two near-identical warm themes side by side in the docs. Five presets, as planned — a different five.

  • minimal — land, water, borders, nothing else
  • atlas — printed-atlas paper on a cold sea, dashed boundaries, serif (replaces paper)
  • noir — dark ground, hairline borders, no fills
  • blueprint — white linework on blue, dashed administrative boundaries
  • contrast — solid black and white, accessibility-first
  • Every preset ships a dark-mode block; tokens are role-named so this is a value swap. An explicit palette still wins, because it is applied after the theme and the cascade settles it — automatic dark is the default, never an override
  • Every preset shows a convincing highlighted state — that is the shot people will judge
  • One shared structural stylesheet. Five themes repeating forty rules is five places for them to drift, so the rules live once and read entirely from tokens. The vocabulary grew to carry what the duplication used to: widths, dash patterns, and the fill and stripe ramps
  • Political fill — shipped. Every country a different colour from each of its neighbours, as data-fill. As cheap as predicted: the border mesh already visits every shared arc, so the adjacency graph falls out of the same pass. Four colours suffice for Europe and five for the world
  • Hatching — added in flight. Diagonal stripes over named countries, for the thing a map has to say that is not a quantity: disputed, claimed, excluded, no data. An overlay rather than a fill, so the two readings stack. The first thing to use the <defs> slot reserved in Phase 2 for a pattern
  • Choropleth fill — shipped in 0.7. values and bins, classified by rank rather than by equal intervals, emitted as data-bin for the theme to colour. It was absent from every earlier draft of this plan: an omission, not a decision
  • Relief — shipped in 0.6, and not as planned. This called for filter: drop-shadow(...); a shadow only separates a shape from its ground, where relief needs a lit face and an unlit one. It is a real feDiffuseLighting filter emitted into <defs>, which a stylesheet asks for by name
DeliveredFive presets with dark blocks, two fill modes that need no data, and 25 gallery renders — one for every continent, Antarctica included. Four bugs surfaced only by rendering and looking: prism walls lighter than the tops they carried, a highlight losing to a band on identical specificity, rivers running off the map to the Black Sea, and mercator and equal-earth never turning to face their region — so Asia was drawn from the far edge of a Greenwich-centred projection while the conics and orthographic, which do rotate, looked fine.

Labels

Called the weakest part of the SVG approach, and scoped down accordingly. It shipped stronger than planned, because two of the three things this phase promised to hand-wave turned out to have geometric answers.

The curated anchor table was never built. This plan called for thirty hand-tuned overrides for Norway, Chile, France and Croatia. What shipped instead finds the anchor by geometry: the balance point of the largest piece of the country that is on the canvas, and where that falls outside the country — every crescent, every Croatia — the point furthest from any edge, found by refining a grid. A table would have gone stale the first time the source data moved; the geometry cannot.

And the fit test could not tell a scattered country from a small one. It measured a name against the width of the shape beneath the anchor — right for a landmass, wrong for an archipelago, so Philippines was written into every document and then hidden, because no single island is as wide as the word while every printed atlas sets it across the whole group. Fixed on the way into Phase 8: when a country is more than one piece and no piece can hold its name, the room it has is the reach of the group, and the name overhangs from an anchor that does not move — so the change can reveal a name and never relocate one. It reveals Philippines on every map of Asia, and Angola, Chile, Fiji, Japan and Indonesia on the world maps. Brunei and Timor-Leste stay hidden, which is what the test is for.

Collision detection was documented as absent and then written anyway. A world map with every capital on it is 470 labels and unreadable. The suppression is greedy and first-come rather than a real placement solver, ranked so the important names win — but the honest description is no longer "none".

  • Country names anchored by area-weighted centroid, falling back to pole-of-inaccessibility by grid refinement
  • Two-line wrapping at the most even word gap — what rescues United Kingdom, South Korea, Papua New Guinea
  • data-rank and data-fit on every label: the engine states facts, the stylesheet decides what to hide
  • --label-advance, the channel by which a stylesheet tells the geometry its own font metrics — SVG cannot measure text outside a browser
  • Five typefaces as a third preset axis, reusing the palette machinery exactly
  • A names option taking caller-supplied words, which covers every language without vendoring translation tables
DeliveredNames on every preset, verified by rendering and looking rather than by string assertion. Three fixes came out of that: a country name colliding with its own capital's name, Croatia anchored in a 0.7-pixel-wide arm, and a world map that was mush until suppression landed.

This was called Ship, and it bundled two different things: being ready to publish and publishing. Only the first is engineering work, so they are split. Publishing is now a decision that happens when it is asked for, and nothing downstream waits on it — the tool can build against the repository.

Annotations

The journalist's actual need: a dot where the thing happened, a label pointing at it. Every hook this requires already exists by the end of Phase 3, so this is composition rather than surgery.

  • map.invert([x, y]) — shipped. The gap this plan never noticed, and the one piece the rest of the phase had to be built on top of. project() turns a coordinate into pixels, which is everything a developer placing a pin by hand needs. A person dragging a pin works the other way: the drop happens in pixels and has to be stored as lon/lat, or the icon detaches from the ground the moment the region or projection changes. The work turned out not to be the inverse but knowing when there isn't one: d3 clamps its inverse trigonometry rather than failing, so a pixel past the edge of an orthographic globe comes back as a coordinate on the limb instead of as nothing, and the corner of a canvas invents a place in the Atlantic. So the answer is put back through the projection and checked against the pixel it came from — a real point returns within a thousandth of a unit, a clamped one misses by more than twenty
  • Pins — shipped. pins: [{ at: [lon, lat], label?, id?, kind?, offset? }], rendering into .mp-annotations. This is where the annotation API got decided rather than where one primitive got built: arrows, callouts and icons all have to say where, and they will all say it this way. at takes a coordinate and nothing else — accepting an ISO code or a place name is cheap to add later, since widening an option breaks no caller, while deciding today what at: "Springfield" means settles a question no real map has asked. Wanted, and deliberately deferred: from: "Odesa" reads better than a pair of numbers and is the form a person writing a story would reach for. It waits on three answers nobody needs yet — what happens when two settlements share a name, whether it means the bundled name or the one names rewrote it to, and what a code resolves to when its country is off the frame. The same bargain neighbours took with its distance and code-list forms: a widened option breaks no caller, so it costs nothing to wait for a real map that wants it. And the far side of a globe had to be caught, which the plan did not foresee: this is the invert() clamping problem running backwards and it is worse, because project() hands a Pacific coordinate a perfectly plausible pixel in the middle of Angola and nothing in the markup says it is wrong. Same guard, other direction — a coordinate that survives the round trip was visible; one that does not is dropped rather than mirrored. A mark that is real but off-canvas is drawn carrying data-fit="0", the same bargain the labels take
  • A fourth and fifth, caught by a test rather than by a render — which is the point. Four of this phase's defects were one mistake wearing different names: a preset copying a neighbouring value into a token nothing consumed yet, where it sat unverified because nothing drew it. Nine reserved tokens are in exactly that position today, set by every preset and never once rendered. What cannot be checked is whether they look good; what can is that each differs from the thing it will be drawn against, because a tint the colour of its ground is not a tint. That test found contrast — the accessibility-first theme — setting --glacier to exactly --land, so ice would have rendered as nothing, and inheriting a black --road onto black land in its dark block. Both were years from being drawn and are fixed now
  • And a third, in the same family, found by looking at the finished deliverable. --anno was a byte-for-byte copy of --accent in all nine presets — harmless while nothing read it, and wrong the moment something did. On the one map this layer exists to make, a region with a highlight and a mark on it, the pin, the leader and the balloon were all drawn in the highlighted country's own colour. The casing hid half of it: a cased mark survives a colour it matches and a filled box does not. Every preset now takes a deeper shade in light and a lifted one in dark, the box is outlined in --anno-ink, and a preset test asserts --anno differs from both --accent and --label-halo. Three of this phase's defects have now been in the annotation tokens, all three from presets copying a neighbouring value into a token nothing consumed yet
  • Two defects found by rendering and looking, both in the reserved tokens. --anno is set to the same value as --accent in all nine presets, so the first pin dropped on a highlighted country was drawn in the country's own colour and disappeared — on precisely the map named in this phase's deliverable. The mark is cased in --label-halo now, the same casing its label gets. And --anno-ink equals --label-halo in every preset, because what it was authored to mean is ink drawn on a mark: filling a pin's label with it would have painted white on white. It stays reserved until a callout has a box to put ink inside, and the label takes --ink like every other name on the map
  • Callouts — shipped. callouts: [{ at, text, offset?, width?, id?, kind? }] — the same at, the same validation, the same round-trip guard, which is what settling the pin first was for. It is a second primitive rather than an option on the pin because the two differ in which half carries the meaning: a pin says there is something here and the mark is the subject, a callout says this sentence is about here and the words are. Hence the box — a word sits on a coastline behind a halo and a sentence does not — and hence no mark at the anchor, since the leader already ends there and a caller who wants a dot adds a pin at the same coordinate. offset places the corner of the box nearest the point and the box grows away from it, so the sign of the offset is the direction it goes and the leader always lands on a corner you can predict
  • And the box had to teach the width estimator two things. SVG cannot measure text outside a browser, so a box is sized from --label-advance — which the label engine deliberately tunes to read low, because a name that does not fit is hidden and over-reading would hide names that fit. A box fails the other way round, and the first render printed its caption straight out through the side. So it rounds up 30%, measured in a browser across the three bundled stacks at three weights, where a realistic caption runs at most 1.28× the estimate. Then noir did it again: --label-track was being read by nothing at all, and 0.3 units per character over a twenty-character line is six units the box never had
  • Arrows — shipped. arrows: [{ from, to, bow?, id?, kind? }]. The first primitive with two coordinates rather than one, so the locator settled for the pin has to hold twice over — and an arrow with either end behind a globe is dropped whole, because half an arrow is a line pointing at somewhere the reader was never told about. bow is how far the curve leaves the straight line and its sign is the side it bows to, which is how a caller gets one off a coastline or out from under another running the other way. Drawn beneath the pins and callouts: a connection is context for the things it connects, not the reverse. And the head caught a fourth instance of an old failure — marker-end is a presentation attribute the flattening pass did not carry, so an arrow exported for a reader that ignores stylesheets would have arrived as a line with no head, exactly as the choropleth once exported flat and the prism once exported as a silhouette. Found by reading the list this time rather than by looking at the render
  • Maki — shipped, 29 icons. A pin's kind doubles as the icon name; there is no separate option, because the vocabulary's names are the conventional values for kind, which is what it was reserved for. A kind naming no icon stays a plain mark and keeps its data-kind, so a caller's own category goes on working. Inlined per pin rather than referenced from a <symbol>: a <use> puts its content in a shadow tree where a class-based fill is unreliable and unreachable by the flattening pass, and duplicating a few hundred bytes is much the cheaper mistake than an icon that vanishes on export. And the vendoring script nearly shipped 29 blank marks — Maki carries line breaks inside its d attributes as &#xA;, which escapes on the way into the document and arrives as literal text no path command recognises. It decodes and then validates now, and a test asserts the same of the committed data
  • The geopolitical half is measured now rather than asserted. Maki has 215 icons and no oil, natural-gas, pipeline or mine. Checked, not assumed. Drawing them to Maki's weight and grid is Phase 13
  • Two icon vocabularies, because the map needs both. Maki covers what sits on the ground — airport, rail, hospital, factory, port — and is CC0, drawn for maps at small sizes. What it does not cover is the geopolitical half a news map runs on: capitals, military, oil and gas, border crossings, conflict, pipelines. Those have to be drawn, to Maki's weight and grid, rather than borrowed from a second house style that would sit visibly beside it. Moved to Phase 13, because nothing engineering-shaped is left in it
  • Public domain only, on both halves. A set that requires a credit line propagates that obligation into every map anyone generates, which is what rules out Tabler (MIT) and Lucide (ISC) however good they look. Inlined as symbols — never external references
  • All of it rendering into the mp-annotations group reserved in Phase 2 — now live rather than reserved
  • The SVG ids are scoped — done, and done before the icons rather than after. They were constants while the stylesheets were properly hashed, so two maps in one document shared mp-land-clip, mp-stripe and mp-relief and every reference resolved to whichever map the parser met first. Three names then; an icon set would have made it three plus one per icon, and the tool's live preview was blocked behind it either way. The authored name is unchanged — a theme still writes url(#mp-relief) — and only the emitted pair moves, together. scripts/build-gallery.mjs had been rewriting ids by hand since the contact sheet landed, which fixed the gallery and nobody else's page; that workaround is gone
  • The icon half wanted its own planning pass, and now has its own phase. Two vocabularies, one of which has to be drawn to Maki's weight and grid, and both public domain — a design job with a licensing constraint, not an afternoon. That is Phase 13 rather than an item left open behind a phase that is otherwise finished
DeliveredA story-ready map: region, highlight, marker, and a captioned callout — one gallery entry carrying all four, a second carrying three arrows out of one port, and a third carrying six Maki icons and one mark that names none. The geopolitical icon set was the one thing left, and it left with its measurement rather than staying open here — Phase 13, a drawing job rather than an engineering one. Two defects came out of rendering that entry and looking at it, and neither would have failed an assertion: the caption overflowed its box, and the pin was labelled Odesa corridor while sitting on Kyiv's coordinates.

Furniture

This phase predicted its own promotion and was right. It was written as deferred-to-v2, built with the tool, on the reasoning that a developer can append a credit line by hand but someone downloading a file from a browser cannot. The tool's specified flow now has building a legend as one of its five steps, so furniture is no longer optional-with-the-tool: it is a prerequisite for it.

Everything that belongs on the canvas rather than on the map. The test for whether furniture is library scope or tool scope is who cannot live without it: a developer using the library can append a credit line to the SVG in three lines, or caption it in the surrounding HTML. Someone who picks a region in a browser and downloads a file has no such option — the credit has to come out of the generator or it does not exist. Nothing forces it earlier either, since Natural Earth is public domain and requires no attribution.

  • A text credit line — shipped. credit: "…" or { text, anchor }, at one of nine canvas positions, styled from --furniture-ink. The anchor is to this layer what at is to the annotations: the decision the watermark, the legend, the scale bar and the north arrow all copy. It carries an alignment as well as a point — a credit anchored bottom-right is text whose end sits there, and placed by coordinate alone a long one runs off the canvas. The test that matters is that the same credit on four regions under four projections lands on the same pixel, because the moment it moves it has stopped being furniture
  • Watermarks — shipped. A wordmark or a logo, the logo read from disk and embedded as a data URI so one file stays the whole map. Given a box and fitted inside it rather than sized to it, because the library cannot measure an image's aspect ratio outside a browser — the same wall --label-advance exists to get around. Text and image are exclusive: a logo above a wordmark is a lockup, and a lockup's proportions belong to whoever owns the mark. With this, 8c is complete except the legend, which stays deferred to v2 by decision
  • A legend driven by the same tokens the theme uses, so the swatches cannot drift from the map. The tool's version pairs each placed icon with a meaning, which makes the legend a view of the annotation layer rather than a separate thing to keep in sync
  • Placing it is two modes, and the second is the hard one. A legend on the map is furniture: anchored to one of nine canvas positions, no camera involvement. A legend beside the map means the canvas grows and the map's viewport shrinks — which reaches back into framing, because fitExtent has to solve for a reserved gutter rather than the whole canvas
  • Scale bar — shipped, and this plan's rule for it was wrong in both directions. "Meaningful only for the conformal and equal-area projections" was never measured. Sampling local scale across the whole drawn canvas, both axes: europe/mercator varies by 2.76 and mercator is conformal, so the rule would allow a bar that lies by nearly three to one; IN/orthographic varies by 1.07 and orthographic is neither family, so the rule would forbid one closer to true than the bar it just permitted. Honesty depends on the extent, not the projection family, and it is measurable. scaleBar: true samples the frame through project and invert and draws a bar only where max/min sits inside tolerance, default 1.1. Same discipline as the invert() round trip: measure the property, do not assert the category. The number is always 1, 2 or 5 × 10ⁿ, so the width is derived from the number — a bar reading 237 km is a bar nobody can step across a map. Verified by laying the drawn length down in three places on each canvas and asking the sphere how far that is: worst error 3.8% across eight maps
  • North arrow — shipped, gated the same way and on the same measurement. It is the narrower of the two claims: a conic fitted to a region holds its scale to three per cent while its meridians fan 22° apart at the corners, so west-europe/conic-conformal earns a bar and no arrow while europe/mercator earns an arrow and no bar. Neither fact is derivable from the projection's family, which is the whole point. Tolerance in degrees off vertical, default 5 — five degrees moves the tip of a 26-unit needle by about its own width where it tapers
  • The refusal is inspectable. map.distortion() returns { scale, north, kmPerUnit, samples }, measured once and kept. A caller who asks for a bar and gets none can answer by how much rather than guess — and Phase 09's tool needs exactly this to tell someone why the box they ticked drew nothing
  • All of it anchored to one of nine canvas positions, never to a coordinate
  • Treat a watermark as attribution, not protection. It is a text node in a file the reader can open — it marks provenance and it cannot enforce anything. Say so in the docs rather than letting anyone assume otherwise

A design pass, deliberately last. 09a–09e build the thing by capability, one piece at a time, and a form assembled that way is a list of every option in the order they were implemented — which is nobody's idea of how to make a map. This is the phase that arranges it around what a person is actually doing, and it is scheduled after the tool works rather than during, because you cannot lay out a screen whose contents are still arriving.

It is also the phase for everything that got noticed while using it and was too small to interrupt for. Those are collected here rather than fixed as they appear, so the map-making does not turn into a stream of one-line UI commits.

  • The form is a workflow now. Subject, Frame, What it shows, Marks, Look. The projection and the canvas decide one thing between them — what is in the picture — and sat in different groups for no reason but history; Neighbours joined them, because it is about what falls inside the frame rather than about a layer somebody wants. Layers and Names merged, since they answer one question between them. Which creates a trap and so comes with the way out — once a bare address reopens the last map there is no way to ask for a blank one, and Start over forgets and reloads.   • The preview has a scale of its own. Fit stays the default, being right for choosing a region; 50%, 100% and 200% are multiples of the canvas's own units, so 100% is the size the file will actually be, and larger than the room available is the point — the frame scrolls rather than crops. What shipped. MapResult.omissions() answers what was asked for and is not on the map — absent, the codes this detail tier does not carry, and unseen, the ones drawn smaller than the dot standing on them. Three things were found by rendering and looking that this page did not know. The contested-area hatch was invisible under land cover — it shipped in mp-land and the paint order puts terrain above it, so every map with terrain on carried a hatch that was in the document and could not be seen; the overlays now paint in borders, under the boundary lines. An enclosed microstate was painted over by the country around it — features arrive in the data's order, which put Vatican at path 0 and Italy at path 25, so a heavy outline changed nothing because the outline was underneath; the land layer now paints largest first. Four sea anchors fall on land, and one of them was drawing: alps-cover has carried Strait of Gibraltar set across Morocco since sea names shipped.

The threshold was measured, not rounded. A rank-1 place dot is 6.4 user units across, and a country smaller than the dot standing on it cannot be seen underneath it — which is what every 1:1 crop of a microstate shows: the dot and the capital's name, and no country. It scales with the canvas the way a fixed list would not; Malta leaves the list at 4000×2000, Vatican never does.

The four defects as they were first written down, on 2026-09-06:

Four defects found in one sitting, on 2026-09-06, all by a person using the tool and none by a test. They look unrelated and they are one thing: the map quietly declines to show part of what was asked for, and nothing anywhere says so. A reader cannot tell the difference between "this country is not in your region" and "this country is in your region and the map could not draw it". That is the defect — not any individual omission.

  • No ocean is ever named, and the seven ocean names ship in the data. Raised while using the tool, 2026-09-06 — and the cause is a rule this project wrote down on purpose in 08c and has now been billed for. A sea is named when its interior point is on the frame, because the polygons were thrown away at build time to save 1.5 MB and only an anchor kept. That is right for the Aegean and wrong for every ocean there is: an ocean's middle is never on a regional map. All seven are vendored at rank 1 and none of them can ever draw — Arctic, Indian, North and South Atlantic, North and South Pacific, Southern. A second defect sits underneath it and is sharper: the pole-of-inaccessibility search puts the Indian Ocean at 92.8°E, 80.6°S and the Southern Ocean at 101.0°E, 80.6°S — the same latitude, both jammed against Antarctica, where the Indian Ocean's middle belongs nearer 20°S. So even a world map, the one frame where the rule should work, labels it in the wrong place. The fix is the one 08c already named and deferred: vendor the marine polygons back and label the visible part of a sea whose middle is off-frame, rather than the sea whose middle is on it. The weight was measured then and is the reason it waited — what has changed is that somebody wants it, which is exactly the evidence the deferral was waiting for
  • Microstates are drawn and cannot be seen. Measured on europe at 50m: at a 960×620 canvas Vatican is 0.2 × 0.1 px, Monaco 0.8 × 0.7, San Marino 1.5 × 1.6, Liechtenstein 1.7 × 3.5, Andorra 4.3 × 3.6, Malta 5.4 × 4.6. Shapes do scale with the canvas — at 4000×2000 Malta reaches 18 × 16 and Andorra 15 × 12, both legible — but Vatican reaches 0.5 × 0.5 and Monaco 2.7 × 2.2. There is no canvas size at which those two appear. At 110m they are not in Natural Earth at all, so 39 countries are drawn where 45 were asked for
  • No small country ever gets its name, at any size. Not one of those seven has a visible country label at 960×620, at 2000×1300 or at 4000×2000. The fit test is behaving correctly — it compares the name against the shape — but the type does not shrink as the map grows, so "Luxembourg" needs about 64 units of width whatever the canvas, and Luxembourg is 32 units wide even at 4000×2000. A bigger canvas buys shapes and never buys names. Luxembourg is the instructive case: big enough to see, too small to letter, and its capital shares its name — so the reader sees a shape labelled Luxembourg and is looking at the city
  • Outlying territories are dropped, by design, and silently. core() in framing.ts ranks each piece of a country by distance from its largest piece and keeps what falls inside max(extent × REACH, MIN_RADIUS). That is what stops West Europe acquiring Guadeloupe, and it is the same pass that removes the Canaries, Ceuta and Melilla from Spain, and the Azores and Madeira from Portugal. Spain at 110m is a single subpath. The rule is right; its silence is not
  • The list of countries you may choose depends on the Detail dropdown, and nothing says so. The tool's picker is built from countryTable(detail), which is 177 countries at 110m and 241 at 50m — the two numbers are written in the source and their consequence is not. The Maldives is not in the list at 110m, nor are Vatican, Monaco, San Marino, Liechtenstein, Andorra or Malta. Worse than absent from the list: choose the Maldives at 50m, switch to 110m, and it leaves the map without a word. south-asia names eight countries and draws seven
  • The two preset exports disagree. REGION_PRESET_NAMES has 28 entries and REGION_PRESETS has 27 — world is a name with no code list, presumably because it means "everything" rather than a list. Both are public API, so anything that iterates the names and looks up the entries gets undefined. Found by a throwaway script doing exactly that on its first preset
  • A missing code leaves a hole rather than a gap. Already filed from 2026-08-30: EH, Western Sahara, is absent from the hand-written region list, so the sahara-cover gallery map has a void between southern Morocco and Mauritania. Same family — the map looks finished and is not

The inset box is the answer to the third and the user's own suggestion: a small framed square in a corner carrying the territories the framing pass removed, drawn at their own scale, exactly as every printed atlas handles the Canaries. The groundwork is already laid — Phase 01 made the projection registry a lookup table rather than a switch statement precisely so that insets and composite projections would not need new geometry code, and that reasoning is in the "built now, used later" table above.

The user's own ordering, and it settles the design: the country must be included; the name is secondary. Being able to see that a country is there is the map telling the truth about its own subject. Being able to read which one it is is a convenience that a legend, a hover title or an inset can supply instead — and every one of these countries already carries a <title> for hover and a data-iso in the markup. So visibility ships first and naming is a separate question, and if the naming half turns out to be expensive it can move to its own phase without leaving the first half undone.

The first two want a different answer, and it should not invent geometry. The library's rule is that it states facts and the theme decides appearance, so the shape of the fix is a fact on the markup — a country whose drawn extent falls below a measured threshold carries an attribute saying so, and a theme gives it a stroke heavy enough to read as a dot. The polygon stays truthful; only its rendering changes. A name that cannot fit inside such a country should be allowed to sit beside it the way a settlement name does, rather than being suppressed. The threshold has to be measured before it is chosen, on the same evidence as the neighbour floor was — render across the range and look, never pick a round number.

Start with counting, because it needs no threshold and no judgement. Every item above except the sub-pixel ones is answered by comparing the ISO codes asked for against the data-iso values actually emitted, which is exact rather than a matter of taste — the map either drew the country or it did not. That one check catches the Maldives at 110m, the six microstates at 110m, Western Sahara, and every future preset that names a code its tier does not carry. It is also the only part that can be a test, and a test is what stops this class coming back. The thresholded parts — how small is too small to see, where a name may sit — want rendering and looking, and should follow rather than lead.

Why this is a phase and not a bug list. Each item alone reads as an edge case worth shrugging at. Together they are the reason a person cannot trust the map for the thing this library is for: a journalist on a deadline who asks for Spain and gets Spain-without-the-Canaries, with nothing on the page admitting it, has been given a wrong map that looks right. That is the failure mode this whole project has been built to avoid, and it has been present since Phase 01.
